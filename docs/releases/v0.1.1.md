TALOS **v0.1.1** makes the first task easier to start and the next task easier to pick up. Open the cockpit, choose which agent writes and which reviews, confirm the task, then inspect the result without leaving the terminal.

## What changed

- **Guided cockpit.** Choose a Git project when you launch from another folder. `/config` opens independent Writer and Critic CLI and model settings. Task review shows the roles and checks before dispatching a single task.
- **Fresh sessions and saved results.** `/new` opens a clean working view with fresh conversations for the next task. `/history` keeps earlier results, reports and saved Git changes within reach.
- **Easier recovery.** Drafts stay editable when Git changes or an unavailable CLI block a run. The cockpit can cancel an unstarted queued task and provides sign-in guidance for recognized provider errors. Input supports Unicode editing, repeated Backspace, word deletion and multiline paste.
- **Local state and reports.** Startup uses Git's local exclude rules for runtime files. Reports are stored under `.talos/reports/` by task ID.
- **Pair and Team improvements.** Team adds advisory triage and a bounded rebuttal loop. Review rounds can stop when changes stagnate. Deferred findings are kept with the task, and failed verification prevents completion.
- **Release distribution.** The release workflow packages macOS and Linux for x86-64 and ARM64, with SHA-256 files and a generated Homebrew formula. `talos doctor` identifies the running binary to help diagnose duplicate installs.

## Install or upgrade

Download the archive and checksum for your platform from the assets below. With Homebrew, use `brew update && brew upgrade AVP-Dev/apps/talos` once the tap publishes this version. Use `talos --version` and `talos doctor` to check which copy is running.

Existing project settings and history stay available. If an earlier installation created a local `.gitignore` edit or a root-level `TALOS_SUMMARY.md`, review those existing changes before starting a new task.

## Verification

On macOS Apple Silicon, the project profile passed formatting, Clippy, 169 tests, the release build and the security scan. Two tests were ignored in the top-level test run. A terminal smoke run used local CLI fixtures to execute two tasks in one instance, exercise recovery guidance, and reopen a saved Git diff. Provider authentication and the complete adapter–platform matrix require separate acceptance.

The native recording uses the current source build, which also wraps output in narrow terminal panes. The downloadable v0.1.1 binaries were built from the release tag.
